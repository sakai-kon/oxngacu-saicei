# Music Search

iTunes Search API を利用した、GitHub Pages対応の静的な音楽検索サイトです。

## 主な機能

- 曲名・アーティスト名で日本の iTunes カタログを検索
- 1回の検索につき最大10件を表示
- ジャケット画像、曲名、アーティスト名、アルバム名、ジャンル、曲の長さを表示
- ジャンルによる絞り込み
- 曲名・アーティスト名・リリース日の並び替え
- 最近の検索履歴（ブラウザの localStorage に保存、最大8件）
- 検索結果のメモリキャッシュ（5分間、最大12検索）
- APIへの連続アクセスを抑えるクライアント側の簡易レート制限
- APIから試聴URLが返る曲は独自プレイヤーでストリーミング再生
- 再生 / 一時停止、10秒スキップ、シーク、音量調整
- 同時に複数のプレビューが再生されないよう制御
- Apple提供のiTunes Storeバッジとプレビュー帰属表示
- 入力クリアボタン、Enterで検索、Escで入力クリア、/キーで検索欄へ移動
- PC・タブレット・スマートフォンに対応

## 技術構成

- HTML / CSS / Vanilla JavaScript
- iTunes Search API
- サーバー・ビルドツール・APIキー不要

## ローカルでの確認

```bash
python -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。

## GitHub Pages

GitHub のリポジトリ設定から **Settings → Pages → Build and deployment → Deploy from a branch** を選び、Branch を `main`、Folder を `/ (root)` に設定してください。

## キャッシュ・利用制限について

- 検索結果のメタデータを、ページを開いている間のメモリに5分間保存します。
- 試聴音源ファイル自体は取得・保存・キャッシュせず、独自プレイヤーからAppleのプレビューURLへストリーミング再生を要求します。
- 標準音声コントロールを使わず、サイト内の再生ボタンとシーク操作を使います。プレイヤーのURLや通信はブラウザから技術的に確認できるため、ダウンロードを完全に防止するものではありません。
- Appleの案内ではSearch APIは約20回/分が目安のため、このサイトでは新規APIリクエストを18回/分に抑えています。制限値は変更される可能性があります。
- この制限はブラウザ単位の簡易対策であり、サイト全体の利用量をサーバー側で制御するものではありません。

## 注意事項

- AppleのSearch API規約では、曲やミュージックビデオのプレビューはストリーミングのみ許可され、ダウンロード・保存・キャッシュは禁止されています。そのため、このサイトには試聴音源の保存機能を設けていません。
- 試聴音源が返されない楽曲は再生できません。試聴はフル尺ではありません。
- ジャケット画像・試聴音源・バッジ・ストアリンクはAppleの利用条件および表示ガイドラインに従ってください。
- このサイトは検索結果を表示する独立した非公式サンプルで、Apple の公式サービスではありません。
